# Retrospective sourcing audit

**Date:** 2026-09-12
**Author:** Claude (professional-knowledge stream)
**Trigger:** Director instruction — _"Anything previously done that can be done better now, should be done better,"_ following `project-intelligence-analysis` being revisited under `GAN_CLAUDE_RESEARCH_SOURCING_STRATEGY.md`'s broader practitioner-evidence model.

**Method:** re-examine every Claude-authored candidate pack's primary source(s) and ask one question: _if this pack were being built today, with the broader sourcing model available, would a genuine practitioner source (GDC talk, shipped-title postmortem, credentialed community expert) beat what it currently cites?_ Not "could more sources be added" — packs that already use a genuinely fitting, authoritative source are left alone. Quality over count applies here exactly as it has everywhere else in this program.

## Priority order for follow-up passes

1. **`game-production-core`** — weakest game-specific grounding, real owning agent (`production-lead`), most central to GAN's actual production-tracking purpose.
2. **`game-art-direction`** — explicitly built as a stopgap before the broader strategy existed; the two 2D-art GDC talks already sourced for `2d-game-art` prove the source class exists and is reachable.
3. **`game-design-core`** — MDA is worth keeping as a citation, but pairing it with a shipped-title design account would substantiate `mechanics_design`/`balance_design` more concretely.
4. **`game-qa-core`** — lowest urgency of the four; WCAG-EM's scoped-evaluation discipline is still professionally sound even though it's not game-specific, so this is more "would be better" than "is currently misleading."

Each upgrade follows the same discipline as every pack in this program: verify the source and its license directly (not from a search summary), read the actual content (transcript or full article, not a title/snippet), cross-check at least one claim where practical, and version the pack forward rather than silently rewriting an already-reviewed one. `game-production-core`, `game-design-core`, and `game-art-direction` are all still `state: draft` and unreviewed, so a version bump (`1.0.0` → `1.1.0`, or `1.1.0` → `1.2.0` for `game-art-direction`, which is already at `1.0.0` from its first pass) with a `supersedes_version` is the right mechanism, same as any other correction.

**A second, mechanical finding surfaced while fixing #1, applied immediately rather than queued:** every prior successor pack that carried an `evaluation_id` forward unchanged from its base version (`game-ux-core@1.1.0`, `game-engineering-core@1.1.0`, `game-qa-core@1.1.0`, and now `game-production-core@1.1.0`) had left that `evaluation_id`'s benchmark fixture's `applies_to_versions` naming only the _original_ version, even though the successor version still lists that same `evaluation_id` and the underlying method is unchanged. This is a correctness gap, not a sourcing one — the validation sweep's own parity check only verified the _union_ of `applies_to_versions` across all fixtures matched the _union_ of `evaluation_ids` across all pack versions, which let a per-version gap slip through undetected in three earlier passes. Fixed all four affected fixtures (`ux-method-contract`, `ux-source-provenance`, `engineering-boundary-contract`, `engineering-method-contract`, `qa-independence-contract`, `qa-method-contract`, plus the two `game-production-core` ones) to list every pack version that actually still exercises them, and **strengthened the validation sweep itself** to check strict per-pack-version completeness (every version's `evaluation_ids` must each resolve to a fixture that names that exact version) rather than only the aggregate union. Re-run across all 37 fixtures and 19 pack-version combinations in this worktree: passes.
